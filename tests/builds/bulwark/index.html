Read a policy

A policy is a key. It opens the rooms written on it, and no others.

  1. allow

    Calls that match go straight to the tool. Narrow them with where: an address, an amount, a table.

  2. ask

    Calls that match wait. The person you name gets a message in Slack, and the call goes through only if they say yes.

  3. everything else

    Blocked. A key opens the rooms written on it; a tool you forgot to list stays locked.

How it works

Every call stops at the desk. Most go straight through.

01

In the doorway. Between your agents and every tool they call.

Bulwark runs as an MCP proxy, or inside your code through an SDK, so it works with any agent framework. Host it yourself or use our cloud.

02

Not on the key, not through the door. The agent gets a refusal it can read.

A call the policy doesn't allow never reaches the tool. The agent hears why, in plain words, and the attempt goes in the log like any other call.

03

Risky calls ring the desk. A named person answers, in Slack.

Lines under ask pause the call and message the approver you chose. The agent waits. Their answer, and their name, go in the log with the call.

04

Every call goes in the ledger. Signed, and searchable afterwards.

Allowed, blocked or asked: each call is written with the policy line that decided it, so "what did the agent do?" has one answer.

How the example reads

  1. Deny lines first. A match stops the call there.
  2. Then ask lines. A match pauses the call for the named approver.
  3. Then allow lines. A match lets the call through.
  4. Nothing matched? Blocked. The key has no line for that room.

Every step, including the approver's answer, is signed into the log.
