# Bulwark (gallery v5) · skill feedback

1. §5.10 / heroSequence() worked first time: one `data-seq-root`, `data-seq="words"` on the h1, two plain `data-seq` blocks, one `rise`. Audit: h1 sharp 1200ms, settled 1890ms. Frames at 100/600/1200/2500ms read right: scene + nav complete, words resolve, lede/CTAs, then the device. It felt premium, not slow, because the 21:9 scene carries the first second.
2. Real wall-clock timing is ~300ms later than `data-seq-end`: `is-in` waits for the module + two rAFs, so the device lands ~2.2s after navigation. Say in §5.10 that the budget is measured from `is-in`, or inline-start the sequence.
3. Audit bug: `copy.h1` reports 16 words for an 8-word h1. `h1.innerText` counts the `.sr-only` copy that `splitWords` prepends. Count `[aria-hidden] .w` or exclude `.sr-only` (every §5.10 build will trip this WARN).
4. Capture tip worth adding to §5.10: a first Playwright run that waited for `data-seq-end` before timing showed the device at "100ms"; time from `goto(..., {waitUntil:'commit'})` and log computed opacity beside each shot.
5. `rise` owns `transform`, so a device centred with `translate:-50%` must use the `translate` property (the §87 CSS already does; say why in a comment).
6. §87 device in the scene: fit well without a cut-out. The foreground plane was a straight crop of the desk strip (`export --crop 0,676,1000,145`) at the same scale, so no masking or seam. Tip for §87: a horizontal counter or desk edge makes the cheapest, cleanest foreground plane. Off on mobile; the device crosses the photo's bottom edge instead.
7. §87 + §5.10 is the strongest pairing in section L: the `rise` reads as the screen coming up from behind the counter. Put the live row (the waiting approval) first, because the desk hides the bottom third.
8. §85 stacked chapters: fit as one colour per thing that happens to a call (cream doorway, oxblood blocked, brass ask, walnut ledger). Bible palette = chapter palette, no new hues. 6px radius, not 28px, kept it in register.
9. §85 trips `layout.textOverlap` even though each panel is opaque and covers the last. Fix that also looks better: fade a panel's content (`.is-covered>*{opacity:0}`) once the next panel is 90% over it. Add it to §85, or have the audit ignore text under an opaque later sibling.
10. §90 methodology as proof suited a product with no customers: a labelled six-call trace against the page's own example policy, the reading order, a before/with table, and "what we can't show you yet" with Placeholder chips. On mobile the trace table works best as stacked rows (time / call / line + result).
11. §86 input as sticky CTA: declined. Bulwark's input is a YAML file written by platform engineers, not a one-line prompt; a fixed bar would duplicate the nav "Book a demo" and sit over the sticky chapters. Note in §86 that it suits single-field products only.
12. §82 fill the blank, reused for conversion: the demo form writes the visitor's name onto the ledger's blank page (multiply, italic display, 3° to match the page). The best small moment on the page; a "form as the photo's object" note in §82 would help.
13. Generated hero: three empty hooks became the counted motif (§83) with dashed ghost tags on a §81 stage. Ask bibles for "N hooks/slots empty" more often; it gives honest numbers to annotate.
