How it reads

Every codebase has paths. A year of pull requests wore them in.

A new engineer doesn’t need a tour of every file. They need to know where people actually walk: which code changes, who changes it, and what the docs say about it. Waypoint reads three things and draws them as one map.

Key to the map

Land
The repository. Every service is a piece of ground with a named owner, or a plain “No owner on record” when nobody has claimed it.
Rivers
The docs. Runbooks, decision records and API notes run through the map, and every answer can link straight into them.
Footpaths
The last year of pull requests. The more people walked a path, the wider it’s drawn. Faint paths are code nobody has touched in a while.
Contours
Directory depth. Closely packed rings mark deep folders, which is usually where a new hire gets lost first.
Waypoints
The first week. Small, real tasks on a route, each with the file to open and the person to ask.

Waypoint reads all of this. It changes none of it.
