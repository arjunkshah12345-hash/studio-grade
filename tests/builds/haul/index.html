Why box by box

Big-bang rewrites stall. The branch drifts, the freeze slips from March to June to “after the launch”, and nobody can review a 900-file diff. Haul moves one module at a time, checks it with your tests, and leaves main green every night.

Three trips, no freeze. Survey the house, move it a box a night, then lock the old door.

  1. Trip 1

    Survey the house

    npx haul survey reads your import graph and packs modules into boxes, leaves first, so nothing gets typed before the code it depends on.

  2. Trip 2

    Move a box a night

    Haul runs as a step in your CI on the schedule you set. Each box is one pull request. A box that fails a test stays where it was, with a note.

  3. Trip 3

    Lock the old door

    When the last box is in, one final pull request turns off allowJs and turns on strict. No JavaScript can sneak back in.

When a test fails

Your tests are the inspector. Fail one, and the box stays home.

  • Nothing half-typed ever reaches main.
  • Haul never edits a test without asking you first.
  • The note and a suggested fix go into MOVING.md.

The moving contract

No customers to quote yet. So here is what we promise instead.

  1. No runtime changes

    Haul adds types and renames files. If the compiled JavaScript differs from main, the box doesn’t ship.

  2. No hidden any

    Every any and @ts-expect-error Haul leaves is listed in MOVING.md with the reason.

  3. Your code stays in your CI

    Haul runs as a step in your pipeline. The open-source CLI runs on your laptop.

  4. Stop on any night

    Cancel and you keep merged boxes and untouched JavaScript. Never a half-typed module.

Does Haul change how my code runs?

No. It adds type annotations, type files and renames. Every box is compiled and compared with main; if the emitted JavaScript differs, the box is held.

Where do the types come from?

From the TypeScript compiler’s inference plus your call sites, tests and JSDoc. When a value genuinely has several shapes, Haul writes any and logs it instead of guessing.

What happens when a test fails?

The box stays as JavaScript, nothing is merged, and the failure and a suggested fix go into MOVING.md. The next night Haul moves on to the next box.

Does our code leave our infrastructure?

No. Team runs as a step inside your own CI runners; the open-source CLI runs locally. The hosted board only receives module paths and status.

Can we pause or set the pace?

Yes. Set how many boxes a night, which folders to skip, and which days to stay quiet, such as release weeks.
