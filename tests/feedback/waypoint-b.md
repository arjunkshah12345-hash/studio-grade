# Waypoint (b): feedback, mostly on xfactor.md

- X2's five lenses worked. The winner, "a printed walking map", came out of the Borrowed format lens only after I wrote X1 as a mechanism ("a year of PRs = paths people already walked"). Suggest: X1 should ask for the product's *input* nouns, because the idea rhymed with the input (PR history = footpaths), not with the output.
- X3 scoring did real work: lens D ("type your repo and the map draws it") scored high on Truth but would have been a faked result. Add an **Honesty gate** to X3: "if the play would show a result the page can't really compute, it's a sample, so label it, or drop the concept".
- X4 "five places" was the most useful line in the skill for this build. It made me put the idea into pricing (folded pocket maps, "Scale 1:50 000" = the 50,000-line Free limit) and into the ending (Friday's "05" written on the waymark disc). Without the checklist both would have been generic cards.
- Missing from X4: **map legends / keys**. When the idea is a symbolic format (map, score, circuit, timetable), the page needs its key in the hero, or the five-second test fails. The key strip in the title block was what made the hero readable.
- X5 needs an example of a *layout* broken rule beside the motion ones: "h1 inside the object's own title block (map cartouche, record label, ticket stub)" read as deliberate and still passed hero.ctas.
- Missing: how to draw **live type in a generated scene so it stays aligned**. I generated a blank paper sheet and printed an SVG map onto it (multiply, §81 stage), then reused the same stage cropped three ways (hero, play zoom, mobile) with CSS custom-property crops. That "one stage, N crops" pattern deserves a line in §81.
- Guardrail that bit me: SVG labels on a printed map need a paper halo (`paint-order:stroke; stroke:#fff` under multiply) and labels drawn *after* routes, or every route crosses a name. Worth a note under imagery §3 / techniques §64.
- Tablet: layout.md's "tablet = mobile composition, wider" saved the hero. At 1024 the in-object title block overflowed its frame; I stacked the title block above a top-row crop of the map instead.
- The audit counted the hero as `lineDrawingHero` (3/6 default traits) even though it's a filled colour map on a photo. That's a false positive for SVG overlays on imagery; maybe ignore SVGs that are layered on an <img>.
