01 · Branches

One trunk. A branch for every pull request.

Production stays the trunk. When a pull request opens, Branchline cuts a copy-on-write branch of it in about a second, so the change runs against data shaped like the real thing instead of a fixture file.

  • Created when the pull request opens
  • Linked in the pull request, beside your checks
  • Deleted when the pull request merges

02 · Seed data

Production rows. Nobody’s personal details.

Each branch is seeded from production with personal data masked. Rows keep their ids, plans and dates, so joins and edge cases behave the way they do in production, without the names and addresses in them.

03 · Schema diff

Read the schema change before you merge it.

Branchline compares a branch’s schema with the branch it came from and shows the difference before merge: added columns, new indexes, dropped tables. Reviewers see what the migration does to the database, not only what it does to the code.

  • Diffs between any two branches
  • Shown before the pull request merges
  • Connect with psql to check it yourself

04 · Lifecycle

It lives as long as the pull request.

Works with

  1. Opened

    Pull request opened against main.

  2. About 1 s

    A copy-on-write branch is cut from production.

  3. Seeded

    Personal data is masked on the way in.

  4. Linked

    The branch shows up as a link in the pull request.

  5. Diffed

    The schema diff is shown before merge.

  6. Merged

    The branch is deleted. Nothing to clean up.
