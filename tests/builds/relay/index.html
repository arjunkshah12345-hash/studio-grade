FIG 01 · comment on api/sessions.go:212

Comments where the code is. Not a summary pasted under the PR.

Relay comments on the exact line, explains the reason in a sentence or two, and offers a suggested change you can commit from the thread. It stays quiet on code it has nothing useful to say about.

  • Suggested changes, one click to commit
  • Reads callers and tests, not only the diff
  • Nits off by default
  • Replies when you push back

FIG 02 · check run on pull request #4417

Bugs caught before merge. Races, off-by-ones, unsafe migrations, missing awaits.

Relay posts a check run on every pull request. You decide which findings block a merge on protected branches; everything else arrives as a suggestion the author can take or leave.

  • Blocking rules per branch
  • Severity you can tune
  • Re-reviews only what changed
  • Links to the commit that fixed it before

FIG 03 · conventions learned in northwind/billing-service

It learns how your team writes code. From resolved threads, not a rules file.

When a reviewer pushes back on a comment, or a pattern keeps coming up in human reviews, Relay proposes a convention. A maintainer accepts it once; from then on it is applied on every pull request in that path.

  • Scoped to paths and languages
  • Every rule cites its threads
  • Accept, edit, or turn off
  • Exportable as plain YAML

Questions staff engineers ask first.

Is our code used to train models?

No. Relay reads code to review the pull request in front of it. Diffs and context are not used to train models, and you can delete a repository’s data from settings at any time.

How noisy is it?

Nits are off by default, and Relay only comments where it can name a concrete problem or a convention your team has agreed on. If a thread is resolved without a change, that counts against the pattern next time.

Can it block merges?

Yes, on the Team plan. Choose which kinds of findings block, and on which branches. Everything else stays a suggestion.

Where do conventions come from?

From your own review history. Relay proposes a convention when the same feedback appears across resolved threads; a maintainer accepts it before it is applied.

Which languages does it review?

TypeScript, JavaScript, Go, Python, Java, Kotlin, Ruby, Rust, C# and SQL migrations, with more on the changelog.
