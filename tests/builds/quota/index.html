Credits and limits

Prepaid credits. Limits that hold.

Sell credits up front and draw them down as usage lands. Give each customer a spend limit, so a runaway loop never turns into a surprise invoice.

The API

One call per event.

Send usage from your API as it happens. Meters, rate cards, credits, limits and invoices take it from there.

The endpoint and keys shown are illustrative.

curl https://api.quota.example/v1/events \
  -H "Authorization: Bearer qk_test_…" \
  -d customer=cus_8812 \
  -d meter=tokens \
  -d model=voice-large \
  -d quantity=1204
await quota.events.create({
  customer: "cus_8812",
  meter: "tokens",
  model: "voice-large",
  quantity: 1204,
});
quota.events.create(
    customer="cus_8812",
    meter="tokens",
    model="voice-large",
    quantity=1204,
)
// 200 OK · example response
{ "meter": "tokens", "reading": 48213906, "invoice_draft": "USD 120.53" }

What counts as billed usage?

The usage charges on the invoices Quota sends for you in a month. The first USD 10,000 of it is free; the 0.5% applies to the rest.

Does Quota replace Stripe?

No. Invoices go out through Stripe. Quota does the work before them: metering, rate cards, credits and spend limits.

What can I meter?

Tokens, requests, seats and GPU-seconds, sent as events from your API. Each model and plan gets its own price in a rate card.

Can my customers see their own usage?

Yes. Embed the live usage dashboard in your app, and they see the same meter you bill from.
